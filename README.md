# Кампус — МУБиНТ в Telegram

Готовый проект для **@RaspisanieMuBINT_bot** и BotHost. В архиве есть исходники и уже собранный интерфейс. Для запуска достаточно Node.js 24 (либо Node.js 22.13 и новее): сервер использует встроенные модули Node, отдельные серверные библиотеки не нужны.

## Версия 2.0 — все восемь улучшений

| Функция | Где искать |
| --- | --- |
| Текущая пара, время до начала/конца, прогресс и следующая аудитория | Верхняя карточка расписания на сегодня |
| Telegram-сообщения об изменениях с «было → стало» и кнопкой нужного дня | Настройки → «Изменения в расписании» |
| Утренняя сводка: пары, время, первая аудитория, ДЗ на сегодня | Настройки → «Утренняя сводка»; выбери время и сохрани |
| Светлая, тёмная и автоматическая тема для всех четырёх сезонов | Настройки → «Твой сезон, твой свет» |
| Фото с камеры/из галереи, увеличение снимков и список дел в ДЗ | Нажми на пару → «Снять фото» / «Из галереи» / «Добавить пункт» |
| Страницы предметов, преподаватели, ближайшие пары и история ДЗ | «Мои предметы»; на телефоне также через «Ещё» → «Предметы» |
| PNG с расписанием дня/недели в текущей палитре | «Поделиться расписанием» над карточкой дня |
| Ярлык на главном экране телефона | «Ещё» / «Настройки» → «Добавить на главный экран» |

**Проверка расписания теперь каждый день в 20:00 по Москве**, включая выходные. Проверяются ближайшие 14 дней. Это расписание работы сервера: приложение может быть закрыто. Старое правило «раз в два дня в 07:30» автоматически заменяется. Напоминания о ДЗ остаются за 3 дня, с 07:30 МСК; утренняя сводка использует выбранное время.

Уведомления об изменениях включены по умолчанию для пользователя с выбранной группой и разрешёнными сообщениями бота. Старую историю при обновлении не рассылаем. Утреннюю сводку нужно **включить в настройках**; время доступно с 05:00 до 11:59 МСК. По умолчанию сводка приходит только в дни занятий.

### Обновление уже работающего бота

1. Останови бота и скачай резервную копию **всей папки `/app/data`**. Сохрани её отдельно: здесь база заданий и фотографии. Резервную копию не загружай в GitHub.
2. Распакуй `mubint-telegram-bothost.zip` и открой папку `mubint-telegram`.
3. Обнови **всё содержимое проекта** в существующем репозитории: файлы в корне и папки `app`, `lib`, `server`, `web`, `seed`, `scripts`, `tests`, `public`. Совпадающие файлы замени. Корневой `app.js` должен остаться в корне, без дополнительной вложенной папки. В этот раз одной замены `app` и `web` недостаточно: обновлён и сервер.
4. Сохрани изменения в ветке, подключённой к BotHost. Настоящие токены, переменные окружения и рабочую папку `data` сохрани на хостинге; архив их не содержит.
5. В BotHost оставь включённым **собственный Dockerfile**. Файл из архива использует **Node.js 24**. Выполни повторное развёртывание из репозитория; простой перезапуск может оставить старые файлы.
6. После запуска проверь `/health`, затем полностью закрой и открой Mini App. В разделе «Изменения» должна быть строка **«Каждый день · 20:00 МСК»**.
7. В «Ещё» → «Настройки» выбери тему и при желании включи утреннюю сводку. Нажми «Сохранить настройки». Если сообщения отключены, отправь `/notifications` боту.
8. Для проверки фото нажми на пару, приложи снимок и сохрани ДЗ. Закрой приложение, открой вновь и проверь фото в «Заданиях».

Схема базы обновляется автоматически: добавляются таблицы фото и настроек, старые ДЗ и история не удаляются. **Не заменяй и не очищай `/app/data`**. Новые переменные окружения не требуются; оставь прежние `BOT_TOKEN`, `APP_URL`, `DATABASE_PATH` и порт.

### Фотографии и задания

- Можно сохранить только фото, только список пунктов или текст в любой комбинации. До **6 фото на задание** и **30 пунктов**.
- Камера открывается через возможности телефона; если прямой запуск камеры недоступен, используй выбор изображения. Снимок автоматически уменьшается до 2400 пикселей по длинной стороне и сохраняется в JPEG; метаданные исходного фото не переносятся.
- Сервер принимает фото до 4 МБ; общий лимит — 200 МБ на пользователя. Снимки лежат в той же SQLite-базе, отдельно от общедоступных файлов сайта. Получить их можно только с проверенной подписью владельца из Telegram.
- Удаление фото в редакторе применяется после сохранения ДЗ. Удалённые из задания снимки очищаются, если не используются в другом задании. Незавершённые загрузки без привязки к ДЗ очищаются после суток во время ежедневного обслуживания.
- Нажми на миниатюру, чтобы открыть снимок; кнопки «+»/«−» увеличивают его, увеличенное фото можно прокручивать.
- Пункты отмечаются независимо. Весь набор ДЗ завершается большой отметкой у задания; выполненные записи остаются в истории.

### Темы и мобильные возможности

Сезон определяется по текущей московской дате: декабрь–февраль — зима, март–май — весна, июнь–август — лето, сентябрь–ноябрь — осень. У каждого сезона есть светлая и тёмная палитра. Режим «Как в Telegram» следует цветовой схеме Telegram; в обычном браузере — настройкам системы. Предпросмотр темы мгновенный, сохранение настроек синхронизирует выбор с аккаунтом.

У ярлыка используется официальный Telegram API с проверкой поддержки. Успешное добавление отмечается только после подтверждения клиента. На неподдерживаемом устройстве показана подсказка, а кнопка отключена.

Экспорт создаётся на устройстве и не требует отдельного сервиса. На картинке сохраняются группа, даты, время, вид занятия, преподаватель и аудитория. Текст личных ДЗ включается **только по отдельной отметке** и кратко; фотографии ДЗ не включаются. Системная кнопка отправки показывается, если браузер умеет передавать файлы. Во всех случаях доступна PNG-картинка для сохранения и последующего прикрепления в Telegram. Недоступные дни не выдаются за дни без занятий: сначала дождись их загрузки. Сохранённые копии помечаются.

Ближайшие занятия на странице предмета берутся из загруженного расписания на следующие шесть недель. Фоновая проверка обеспечивает ближайшие 14 дней, другие даты добавляются при просмотре календаря. Если дата ещё не загружена, страница прямо сообщает об этом.

## 1. Загрузить проект на GitHub

1. Распакуй архив.
2. Создай репозиторий, например `mubint-telegram`.
3. Загрузи **содержимое распакованной папки** через `Add file → Upload files` и сохрани изменения в ветке `main`.
4. В корне репозитория должны находиться `app.js`, `package.json`, `Dockerfile` и папки `web`, `server`, `seed`, `app`, `lib`. Не загружай ZIP одним файлом и не помещай весь проект в дополнительную вложенную папку.
5. Скопируй HTTPS-адрес репозитория. Это адрес исходников, а не адрес мини-приложения.

Если репозиторий приватный, подключи доступ к нему в разделе Git-репозиториев BotHost. В проекте нет настоящего токена или личных ДЗ. `.env` и рабочая папка `data` исключены из Git. При последующих изменениях также не добавляй их в репозиторий.

## 2. Заполнить форму BotHost

| Поле | Значение |
| --- | --- |
| Название бота | Кампус — МУБиНТ |
| Платформа | Telegram |
| Язык разработки | **Node.js** |
| Версия Node.js | **24**, если доступна; иначе **22** не ниже 22.13 |
| Bot Token | Токен именно `@RaspisanieMuBINT_bot` из BotFather |
| Локация | Можно оставить выбранные Нидерланды |
| Git URL репозитория | HTTPS-адрес созданного репозитория |
| Ветка | `main` |
| Описание | Расписание МУБиНТ, личные ДЗ и напоминания |
| Главный файл, если поле есть | `app.js` |
| Порт, если поле есть | `3000` |

Поле главного файла и опции домена находятся в «Дополнительных настройках». Если выбираешь «Использовать собственный Dockerfile», оставь путь `Dockerfile`: включённый в комплект файл сам задаёт Node.js 24 и команду запуска. Он не требует установки зависимостей или сборки на хостинге. Для обычного Node.js-режима команда запуска — `npm start`, то есть `node app.js`.

### Переменные окружения

| Ключ | Значение |
| --- | --- |
| `BOT_USERNAME` | `RaspisanieMuBINT_bot` |
| `TZ` | `Europe/Moscow` |
| `DATABASE_PATH` | `/app/data/campus.sqlite` |
| `PORT` | `3000` — должен совпадать с портом в настройках домена |
| `APP_URL` | Реальный HTTPS-адрес приложения после подключения домена |

Токен из поля **Bot Token** BotHost передаёт как `BOT_TOKEN` автоматически. Повторно добавлять его в таблицу обычно не нужно. Не вставляй токен в GitHub, в HTML или в `APP_URL`.

Если домен пока неизвестен, `APP_URL` можно временно не добавлять: сервер запустится. Когда платформа передаёт переменную `DOMAIN`, приложение использует её автоматически. Но для однозначной настройки после подключения домена укажи полный `APP_URL` явно и перезапусти бота.

Оставь `DISABLE_BACKGROUND` незаданной: проверки расписания и Telegram включены по умолчанию. Переменная со значением `1` используется только для локальной проверки без внешних обращений.

## 3. Подключить HTTPS-домен

1. В настройках бота включи домен/«Использовать домен» или нажми «Подключить домен» в его карточке.
2. Выбери доступный поддомен BotHost. Покупать собственный домен необязательно. Точное окончание адреса выдаст платформа.
3. Внутренний порт — **3000**. Сервер уже слушает `0.0.0.0`.
4. Дождись доступности адреса по HTTPS.
5. Добавь `APP_URL` с этим адресом, например `https://ТВОЙ-АДРЕС`, без дополнительных путей и параметров, и перезапусти бота. Пример не является действующим адресом — используй выданный BotHost.

После успешного подключения в логах появятся «Кампус запущен» и «Бот @RaspisanieMuBINT_bot подключён». Если выводится сообщение о настройке адреса, проверь `APP_URL`. Если токен принадлежит другому боту, приложение сообщит об этом, не подключая его.

## 4. Открыть приложение в Telegram

1. Открой https://t.me/RaspisanieMuBINT_bot и нажми **Старт**.
2. Бот пришлёт кнопку **Открыть расписание**. Кнопка меню **Расписание** настраивается автоматически при успешном запуске с `APP_URL`.
3. Если нужно настроить меню вручную: BotFather → `/mybots` → этот бот → `Bot Settings → Menu Button`; текст «Расписание», адрес — `APP_URL`.
4. Для большой кнопки запуска в профиле: `Bot Settings → Configure Mini App → Enable Mini App`, затем тот же HTTPS-адрес.

Это именно Mini App, открываемое через кнопку бота. Обычное открытие домена в браузере позволяет смотреть расписание; личные ДЗ доступны после подтверждённого входа из Telegram.

Команды: `/start` — запуск, `/homework` — задания, `/settings` — настройки, `/notifications` — включить уведомления, `/stop` — отключить все сообщения, `/help` — подсказка. Бот работает в личном чате.

## Как работают функции

- Сначала выбирается группа, затем физкультура, шахматы или оба варианта. Выбор синхронизируется с Telegram-аккаунтом.
- Расписание показывает лекции, практические занятия, преподавателей и аудитории. Выбор недели и календарь сохранены.
- Нажатие на пару открывает ДЗ. Автоматический срок — следующая опубликованная дата того же предмета и группы. Двойные пары в один день не считаются следующим занятием. Отменённые пары пропускаются. Срок можно выбрать вручную.
- Если следующая пара ещё не опубликована, запись сохраняется в ожидании даты. Поиск учитывает сохранённое расписание на шесть недель после исходной пары. Фоновая проверка загружает ближайшие 14 дней, новые просмотренные дни также сохраняются. После появления даты срок обновляется автоматически; при отмене известной пары срок пересчитывается.
- Проверка расписания всех групп запускается **ежедневно в 20:00 МСК**. Первая плановая дата — 12 октября 2026 года; `SCHEDULE_ANCHOR_DATE` ограничивает только начало расписания, а не интервал. При первом запуске выполняется начальная загрузка. После простоя сервер догоняет пропущенную проверку. При частичной ошибке повторяет её через 15 минут.
- При просмотре расписания сервер также обращается к источнику с общим кешем на пять минут. Изменения сохраняются в истории и показываются в карточках занятий.
- Отмеченное напоминание о ДЗ отправляется **за три календарных дня в 07:30 МСК**. Проверка доставки выполняется каждые 30 секунд после 07:30. Если ДЗ добавлено позже или дата стала известна позже, напоминание отправится при ближайшей проверке до даты занятия включительно. Доставка зависит от доступности хостинга, источника и Telegram; проверка расписания может занять несколько минут.
- Изменения отправляются только для текущей группы и выбора физкультуры/шахмат. Очередь и отметки доставки переживают перезапуск. При смене группы, отключении уведомлений или устаревании дня сообщения отменяются.
- Сводка приходит один раз за день. После короткого простоя возможна доставка в течение двух часов от выбранного времени; вечером пропущенную утреннюю сводку не отправляем. Если источник недоступен, сохранённая версия помечается, а отсутствие пар не выводится из ошибки.
- Выполненные, удалённые и устаревшие версии заданий исключаются из очереди. После успешной отправки сохраняется отметка, при ошибке доставки применяется повтор с паузой. Как у любой отправки через внешний API, аварийный перезапуск сразу после отправки, но до записи результата в БД, может привести к повторному сообщению.
- При сбое сайта вуза приложение показывает сохранённую копию с предупреждением. Ошибка источника не превращается в отмену всех занятий.

Рабочая SQLite-база находится в `/app/data/campus.sqlite`; туда же SQLite пишет служебные файлы. Убедись, что `/app/data` подключена как постоянное хранилище BotHost, сохраняемое между обновлениями репозитория. Для резервной копии останови бота и скачай всю папку `data`. Запускай один экземпляр этого проекта для одного токена.

## Проверка после запуска

1. Открывается HTTPS-домен и страница `/health` возвращает `ok: true`.
2. Бот отвечает на `/start`, кнопка открывает приложение внутри Telegram.
3. После выбора группы видны пары, лекции/практика и календарь.
4. ДЗ сохраняется и остаётся после закрытия и повторного открытия приложения.
5. Для проверки напоминания можно создать помеченное «Напомнить» задание с ручным сроком на завтра. После 07:30 оно должно прийти при ближайшей проверке. Затем удали пробную запись.
6. У другого Telegram-пользователя собственные задания, твои ему не видны.
7. В «Изменениях» после начальной загрузки видно время проверки; при недоступном источнике показаны даты с ошибками.

Проверено: TypeScript, производственная сборка и 21 автоматический тест сервера. В Chromium проверены полные сценарии: ДЗ только с фото, срок следующей пары, увеличение фото, сохранение пунктов, настройки сводки, темы, предметы, экспорт дня/недели и ссылки из уведомлений. Проверены экраны 1440, 390 и 360 пикселей. В браузерной проверке Telegram API и сообщения имитировались; реальная камера, системная отправка, добавление ярлыка и доставка через ваш токен проверяются на телефоне после развёртывания.

Обновление сохраняет существующую базу Telegram-версии. Данные из отдельного старого сайта автоматически не импортируются. Для обычного обновления уже работающего бота сохраняй прежний `DATABASE_PATH` и папку `data`.

## Для дальнейших изменений кода

Рабочая сборка уже находится в `web/` и `server/shared/` и должна оставаться в репозитории. Это позволяет запускать приложение без npm-установки и не терять сборку из-за особенностей монтирования `/app` на BotHost.

Для пересборки исходников на Node.js 24:

```bash
npm ci
npm run check
npm run build
npm test
```

После редактирования `app/` или `lib/` обязательно пересобери проект и загрузи обновлённые `web/` и `server/shared/`. Для локального запуска: `node --env-file=.env app.js` с переменными из `.env.example`. При тестировании без токена используй `DISABLE_BACKGROUND=1`.

Основа интерфейса: принятая версия «Кампус — расписание МУБиНТ» от 11 октября 2026 года. Личные запросы авторизуются только по проверенной подписи `Telegram.WebApp.initData`; переданные клиентом ID и заголовки ChatGPT не дают доступа.
